# ADR 0001–0010 架构决策记录合集

## ADR-0001：客户端引擎与渲染管线
- **状态**：已采纳（v1.1 修订）
- **决策**：采用 Godot 4.7 (.NET / C#) 作为客户端引擎，PC 开发使用 Forward+ 渲染器，移动端（Android）导出使用 Mobile 渲染器。
- **背景与理由**：横屏（1920×1080 基准，兼容 16:9 / 20:9）俯视 3D 低模表现，目标中低端 Android 30fps。Godot 4 的 `MultiMeshInstance3D` 与 `Instance Shader Parameters` 原生支持低开销同屏 48 单位及掩体渲染。

## ADR-0002：纯 C# 模拟层与经营层解耦
- **状态**：已采纳
- **决策**：`FFM.Sim` 与 `FFM.Meta` 为纯 C# 类库（`net8.0`），严禁引用 `GodotSharp`。Godot 工程（`FFIdleDemo.csproj`）仅负责表现、镜头、音效与 UI。
- **背景与理由**：保证模拟核心可在无图形环境下高速批量运行（`FFM.Sim.Runner`）并进行 NUnit 单元测试与 CI 自动化平衡校验。

## ADR-0003：确定性模拟与随机数流
- **状态**：已采纳
- **决策**：模拟固定步长 10 Hz（0.1 s/tick），单局内单线程顺序执行 `Step()`。统一使用自实现 `xorshift128+` 随机数生成器（`FFM.Sim.Core.Rng`），支持通过 `Fork(uint streamId)` 派生子流。
- **背景与理由**：同平台下相同 seed + 相同配置产生 100% 相同的 `EventLog` FNV-1a 哈希与结算结果。禁止 `System.Random`、`DateTime.Now`、`Guid.NewGuid` 及非确定性字典遍历。

## ADR-0004：配置驱动与 JSON 序列化
- **状态**：已采纳
- **决策**：所有可调数值存储在 `configs/*.json`，采用 .NET 8 原生 `System.Text.Json` 加载并由 `ConfigValidator` 校验。`ConfigBundle` 使用 `partial class` 按模块拆分。
- **背景与理由**：Sim、Meta、Runner、Godot Client 共用同一套 JSON 配置数据源，避免引擎专属资产格式导致 Headless 无法读取。

## ADR-0005：渲染-模拟分离、双缓冲快照与 10 秒环形缓存
- **状态**：已采纳
- **决策**：`ISimulation` 内部维护 `PrevSnapshot` 与 `CurrSnapshot` 双缓冲只读快照，每 `Step()` 翻转一次，零堆内存分配。Godot `SimHost` 维护容量为 100 ticks（10 秒模拟时间）的 `SnapshotRingBuffer`。
- **背景与理由**：渲染帧在 `PrevSnapshot` 与 `CurrSnapshot` 间做平滑插值；环形缓存支持导演相机随时一键回看前 10 秒战况。

## ADR-0006：256×256 地图网格与双层导航
- **状态**：已采纳
- **决策**：地图为 256×256 网格（cell = 8m，总计 2048m × 2048m）。导航分为两层：小队宏观转移在 64×64 粗网格（每块 4×4 cells = 32m）上运行带高度/掩体代价的 A*；个体局部移动采用视线直走 + 邻域掩体微调。
- **背景与理由**：避免 48 个单位在 65,536 节点上高频跑全图 A*，确保单核单局（约 10,000 ticks）耗时稳定控制在 40–60 ms 以内。

## ADR-0007：模拟时间与自适应观赛倍速
- **状态**：已采纳
- **决策**：模拟内部使用真实战术时间（8 段缩圈总长约 960 s）。客户端默认以 4x 播放，当玩家队伍连续 60 s 模拟时间内无交火/缩圈/指令事件时，可自动切入 8x 静默快进。
- **背景与理由**：将单局观赛时长控制在 3–5 分钟，兼顾真实 BR 战术节奏与经理游戏爽感。

## ADR-0008：3D 低模美术规范与三级 LOD
- **状态**：已采纳
- **决策**：采用三级镜头 LOD：全图缩放使用聚合 Token（`MultiMesh` / 图标）、中景使用静态低模 + 队色光环、近景交火使用带 4 动作的动画低模。队色通过 Godot `Instance Shader Parameters` 注入。
- **背景与理由**：兼顾宏观战局可读性与微观交火表现力，严格控制移动端 Draw Call（≤ 300）与面数预算。

## ADR-0009：存档架构与版本迁移
- **状态**：已采纳
- **决策**：经营层 `FFM.Meta` 支持全量 JSON 存档，包含 `schemaVersion` 字段与迁移管线；单局过程不存盘，仅归档 `MatchResult` 与关键事件摘要。
- **背景与理由**：确保存档体积紧凑、跨版本向后兼容，且字节级确定性可测。

## ADR-0010：C# 12 编码规范与热路径零 GC
- **状态**：已采纳
- **决策**：启用 `<Nullable>enable</Nullable>` 与 `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`。`FFM.Sim` 热路径禁止 LINQ、闭包、装箱、字符串拼接与异常控制流，`SimEvent` 采用固定大小 `readonly struct`。
- **背景与理由**：消除 GC 尖峰对客户端帧率与批量模拟吞吐量的影响。
