# 单决策归因测试协议 (Single-Decision Attribution Test Protocol)

> **对标文档章节**：§1.1 支柱 2「看得出」 & §10.4 体验验证协议 (`WP-23`)
> **核心验收标准**：只修改 **1 项赛前或赛中决策**（同一定数种子或可控对照样本），玩家在观看比赛或赛后战报后，能在 **不看后台公式** 的前提下清楚感知并复述出该决策在场上造成的可观察行为差异。

---

## 1. 对照实验组设计 (4 组必测单变量对照)

测试使用固定比赛种子（默认 `Seed = 20260416`）或 `FFM.Sim.Runner` 对照模式，每次仅改动 **唯一变量**：

### 实验组 A：跳点与航线冲突决策 (`DropPoiId` 变更)
- **对照组 A0**：玩家战队选择外围低冲突跳点 `rim_nam_village`（无同跳敌队）。
- **实验组 A1**：玩家战队改选核心高价值跳点 `pochinok`（与激进强队 `sq_01_alpha` 同跳）。
- **场上可观察现象要求**：
  1. 落地后 60 秒内，A1 组触发 `EarlyLoot` 阶段的近距离遭遇战、弹道对射与击倒播报；A0 组则在 0 交火状态下平稳完成搜刮并提前拿车转移。
  2. 若 A1 打赢落地团，其装备等级（2~3 级甲/头、冰墙储量）在左侧面板明显高于 A0；若打输则直接触发早期减员或第 12 名团灭（并在赛后战报归因首条明确指出「跳点冲突导致早期团灭」）。

### 实验组 B：主动技能体系切换 (`ActiveSkillId` 变更)
- **对照组 B0**：4 名选手携带全进攻/侦察技能组合（`chrono_shield` + `moco_eye` + `hayato_bushido` + `kelly_dash`）。
- **实验组 B1**：支援位改带核心救援/续航技能 `alok_aura` + `dimitri_healing_heartbeat`。
- **场上可观察现象要求**：
  1. 在中后期交火出现队员被击倒（`Downed`）时，B1 组触发翡翠绿（`#16C60C`）技能光环与快速自救/互救进度，倒地转存活率显著提升。
  2. 赛后战报 `PlayerMatchStats` 中 B1 组的 `Revives` 与 `SurvivedSec` 明显提升，且战报复盘明确提及主动技能与救援贡献。

### 实验组 C：指挥官单参数替换 (`IGL Shotcalling` 差异)
- **对照组 C0**：首发高指挥属性 IGL（`Shotcalling = 88`，`Composure = 85`）。
- **实验组 C1**：仅将 IGL 替换为枪法相同但指挥属性低的新人（`Shotcalling = 52`，`Composure = 50`），其余 3 名队员与战术完全不变。
- **场上可观察现象要求**：
  1. **自主进圈时机**：在第 2、3 圈刷新时，C0 组在缩圈开始前即启动向圈内掩体/高点的提前转移；C1 组出现明显的搜刮恋战与滞后进圈，更容易在圈边被架枪拦截或吃电磁区伤害。
  2. **赛中指令响应**：玩家下达 `HoldPosition` 或 `AvoidFight` 指令时，C0 组几乎瞬时切换战术状态条并执行；C1 组明显出现更高的延迟甚至在交火压力下触发 `CommandIgnored`（抗命/犹豫播报）。

### 实验组 D：疲劳与带伤硬上 (`Fatigue = 85` vs `Fatigue = 15`)
- **对照组 D0**：主力突击手处于健康充沛状态（`Fatigue = 15`）。
- **实验组 D1**：主力突击手连续高强度训练未轮休（`Fatigue = 85`）。
- **场上可观察现象要求**：
  1. 开赛与赛后战报明确标记该选手的疲劳减益或 `OffDay`（状态失常）告警。
  2. 场上对枪时 D1 突击手的先手击倒率下降、被击倒频率上升，赛后战报归因条目直接提示「高疲劳/状态失常导致关键对枪失利，建议下周安排 Recovery 轮休」。

## 2. 验收判定准则

1. **视觉可感知性**：上述 4 组实验中，观察者必须在 **3D 战场画面 + 实时 HUD 播报** 中直接看到至少 1 处显著行为分叉，而非只能去翻赛后数字表格。
2. **赛后战报闭环验证**：赛后自动生成的 3 条核心归因结论（`PostMatchReport.AttributionInsights`）必须至少有 1 条准确命中本次实验改动的根因维度（跳点冲突 / 转移时机与电磁区受损 / 道具与技能释放 / 疲劳与 OffDay 波动 / 指挥官指令执行率）。
3. **数值显著性兜底**：与 `FFM.Sim.Runner --sensitivity` 自动化测试联动，确保各核心维度在 200 局蒙特卡洛对局中的胜率/生存/均分差异全部超过 §10.2 规定的显著性下限。
